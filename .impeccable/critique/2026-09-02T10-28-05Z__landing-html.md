## Design Specificity Verdict

**Earns it in the payload, rents the chassis — and the rented part breaks the argument.**

Content layer is unmistakably authored: seven bespoke inline SVG diagrams each depicting the actual mechanism of the system above them (shelf grid with one facing bracketed, gateway fanning into six named services, conveyor with one dot in a reticle, dashed HUMAN CONFIRMS gate, fisheye arcs with HAND RAISED marker). Hero canvas draws drifting points threading to the cursor with detection brackets spawning and expiring — literally a detector running behind "I teach machines to watch, judge, and report."

Interaction grammar is 2024 award-site stock: preloader percentage, reticle cursor, magnetic buttons, infinite marquee, scroll-pinned reel, count-up stats. All transferable to any product. The pin — the most generic element — is where conversion dies.

**Deterministic scan**: CLI detector UNUSABLE this run. Exit 0 with `[]`, but stderr: `DEGRADED - HTML parser modules unavailable (htmlparser2, css-select, css-tree, domutils). Falling back to regex matching... findings are an undercount, not a clean bill of health.` No node_modules under skill scripts/. Zero is a null read, not a pass.

In-page injected detector = real signal, 97 findings across 11 rules:
- undersized-ui-text 68 (10.5px span.sig, nav links, #clock, tech-tag li across all 7 cards)
- tiny-text 9 (11.5px p.tally, div.out per card)
- call-caps-body 8 (uppercase on 408-char ticker track, 59-char footer)
- kicker-above-heading 4; heading-rhythm 2 (h2 with 28px above / 152px below)
- oversized-h1, hero-eyebrow-chip, clipped-overflow-container (#reel), wide-tracking, em-dash-overuse (17), pulsing-dot — 1 each

Agreement: detector's clipped-overflow-container on #reel + heading-rhythm are the mechanical shadow of Priority Issue 1 — symptom found mechanically, 386px cause found by review. False positives: oversized-h1 (the 120px h1 IS the argument), em-dash-overuse (the voice). Partial: 68 undersized-ui-text hits are real but 10.5px mono is a deliberate instrument-panel idiom in chrome; only the card CTA path instances are severity-worthy.

**Visual overlays**: none rendered. Injection and execution succeeded (97 findings prove it), but detect.js writes only to console; DOM query for [id*="impeccable"] returned empty. Both servers stopped, landing.html untouched.

## Overall Impression

A good page with one load-bearing bug wearing a design decision's clothes. Copy, diagrams, and contrast/reduced-motion engineering beat most award-winning portfolios. Then the evidence section — the reason a hiring manager is still scrolling — is locked inside a scroll-pin that decapitates every card by ~386px on a standard laptop and puts seven keyboard focus stops off-screen.

Biggest opportunity: stop pinning #reel, pin .rail only. One change recovers the proof, the seven CTAs, the keyboard path, and anchor accuracy simultaneously.

## What's Working

1. **The seven diagrams do argumentative work no screenshot could.** They prove he can explain a system — the actual hire criterion. HUMAN CONFIRMS drawn as a dashed gate is method-principle A rendered as a picture: same point argued in two modalities without repeating a word.
2. **Copy written for engineering managers, not portfolios.** "The screen a manager actually opens." "Accuracy checks that skip rather than pass when real validation data is missing. False assurance is worse than none." Abstract claims converted to falsifiable ones — credible before the numbers land.
3. **Contrast and reduced-motion engineering almost nobody ships.** --line-strong 3.26:1 on --surface, --muted 5.3:1, light --accent 4.9:1. prefers-reduced-motion block deliberately KEEPS colour/border transitions so hover/focus feedback survives. Preloader gates inert on covered content so Tab can't land behind the curtain.

## Priority Issues

**[P0] Pinned reel clips every card and buries the per-project CTA**
- What: #reel measures 1320px pinned into an 809px viewport (measured live). .slab bottom at y=1194; `Request repository access` at y=1133 — 324px below fold, in a section pinned so it cannot be scrolled to. Cards 01-04 never reveal body copy, tech tags, outcome figure, or CTA at ANY scroll position. Cause: .reel-head{padding:124px 0 46px} + 659px slab + .rail{padding:0 30px 124px} (line 292). Needs a 1320px-tall viewport; no laptop has one.
- Why it matters: entire evidence section + second-most-repeated CTA (7 instances). On the most common hiring-manager screen the proof is decapitated and the ask is invisible.
- Fix: pin .rail only — move .reel-head outside the pinned element, let it scroll away. Drop the 124px bottom padding. Gate matchMedia on (min-width:1001px) and (min-height:1000px); shorter viewports fall through to the existing wrapped layout, which already works (lines 405/412).
- Suggested command: /impeccable adapt

**[P1] Keyboard focus escapes the viewport inside the reel**
- What: focusing card 4's link puts it at top:1401, left:-499 — off-screen both axes, no visible ring, browser scroll suppressed by the pin. Seven focus stops invisible.
- Why it matters: keyboard and screen-magnifier users lose all seven project links; the carefully-defined :focus-visible outline never appears. The page's own accessibility work undone by the pin.
- Fix: on focusin within #rail, drive ScrollTrigger position to centre that slab (st.scroll(st.start + i/(n-1) * (st.end - st.start))); add .slab:focus-within border treatment.
- Suggested command: /impeccable harden

**[P1] Autoplaying marquee with no pause control — WCAG 2.2.2 Level A**
- What: gsap.to(track, {x:-half, duration:26, ease:'none', repeat:-1}) at line 1013 runs forever. Only handler is a scroll-direction timeScale flip (line 1014) — verified no pause/stop/hide. Reduced-motion users covered; everyone else not.
- Why it matters: Level A failure on a page whose method section is about auditability. Also permanent peripheral motion competing with every heading below.
- Fix: pause on pointerenter/focusin with one real control, or stop after a single full cycle.
- Suggested command: /impeccable harden

**[P1] The name is absent from every mobile viewport**
- What: hero has no name (tagline, h1 thesis, para, CTAs, clock). .dock .sig{font-size:0; gap:0} at line 166 kills the wordmark below 980px — comment reads "keep the live dot, drop the wordmark". #pre footer line vanishes after ~2s. On a phone the name survives only in the closing footer and the mailto address.
- Why it matters: a personal portfolio whose purpose is attaching a body of work to a person. A phone reader absorbs the entire argument without learning who made it.
- Fix: name in the hero — tagline as LE NGUYEN THANH HA — AI PRODUCT ENGINEER, or a line under the h1. Replace font-size:0 with a shortened HA wordmark.
- Suggested command: /impeccable clarify

**[P2] The counts don't reconcile**
- What: "Twelve systems in production. Here are seven." (line 541) then "Four at DFlo · six delivered solo · one at Rainscales · one at Viettel" (line 544, = 12), above a reel with one DFlo card and two Independent cards.
- Why it matters: on a page selling verifiability (797 commits, 75 reviewed PRs), the first number a sceptic checks doesn't add up.
- Fix: make the tally describe the seven shown, or label it explicitly as the full twelve.
- Suggested command: /impeccable clarify
