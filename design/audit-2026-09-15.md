# Portfolio audit — responsive, accessibility, content

**Target:** `index.html` (audited as `landing.html`; renamed for GitHub Pages)
**Date:** 2026-09-15
**Method:** live measurement in headless Chromium at 16 viewport widths × 4 locales × 2 themes;
axe-core 4.10.2 (`wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa, best-practice`); manual contrast
computation against the token set; DOM accessible-name extraction.

Every finding below was measured, not inferred. Every fix in this document is applied.

### 1.1 The phone chrome budget

At 360px the fixed chrome has roughly 330px to spend and five controls that want 400px. The controls
are ranked by whether the device can still do the job without them:

- **Method and Stack jump links** — dropped ≤560px. Both sections are one scroll away.
- **Work jump link** — dropped ≤400px. Same reasoning, and the hero's primary button already goes there.
- **Theme toggle** — dropped ≤560px. The theme already follows the OS setting, so losing the toggle
  costs a preference, not access.
- **Language select** — kept at every width. Nothing else selects it once a link has been forwarded
  to someone whose browser locale is not the language they want to read in.
- **Email pill** — kept at every width, dropping its label to the mark below 560px.

### 1.2 Spacing and hierarchy

Section rhythm is set by three authored tiers, not one, and the tiers are consistent within
themselves: `.pad` sections sit 260–291px apart at 1440 (156–187 at 390), the reel is deliberately
tighter at 69–134px so the cards read as one run, and `.field` is tighter still at 170px. That is a
decision, not drift, and it is left alone.

The previous critique left four spacing and hierarchy defects open. All four were re-measured after
this pass; three no longer reproduce and are recorded here so they are not re-litigated:

| Reported | Measured now | Verdict |
|---|---|---|
| `.close .duo{align-items:end}` leaves a ~220px hole under the close h2 at 1440 | `align-items:start`; h2 bottom → lede top = **24px**, portrait starts 25px below the h2 | Already fixed upstream |
| Ticker "Pause" overlaps the track text at 400px | Zero track items intersect the label at 360 / 400 / 430; the button's 34px gradient mask clears it | Does not reproduce |
| `.also li` "GOLDEN GATE GROUP · 2025" wraps to two lines at 1440 | All three `.also .who` render on **one line** at 1440 in the 232px column | Does not reproduce |
| ~200px empty valley before `#method` on mobile | Band bottom → method heading is 257px at 390, of which ~110px is the band's own lower half; real padding is `.pad`'s 72px plus the eyebrow | Within the authored tier, not a void |

Hierarchy on the first screen was the one live item, and it is R7: the h1 now leads the mobile
viewport at 32.6–39.8px instead of sitting level with 18px body copy.

### Verified clean

- No horizontal overflow at any of 16 widths × 4 locales.
- No headline line clipped by `.ln` at any width × locale after R6/R7, confirmed by measuring the
  glyph run with an inline probe rather than the block width of `.ln > span`, which is always the
  container width and cannot detect a wrap.
- The reel's pin is gated on height as well as width and degrades to a wrapped grid; no clipped card
  on a short laptop.
- `prefers-reduced-motion` suppresses movement while keeping colour and border feedback.
- The print stylesheet re-points the tokens at paper and forces the GSAP reveals visible.

## 2. Accessibility

### Result

**axe-core 4.10.2 — 0 violations** across English / Vietnamese / Japanese / Chinese × dark / light,
at 360px, 390px, 768px and 1440px, and again with `prefers-reduced-motion: reduce` emulated (the
reduced-motion path takes an early return out of the GSAP block, so it is a different DOM).
Before this pass: 1 violation (`region`) and the defects below, which are of a kind axe cannot see.

| # | Finding | Status |
|---|---------|--------|
| A1 | The email pill sat outside every landmark (`region`). | Fixed — both fixed controls wrapped in a `<header>` that collapses to zero height |
| A2 | Two `<section>`s had no accessible name: the metrics strip and the employment timeline. | Fixed — translated `aria-label` on each |
| A3 | The section labels animate through random glyphs on arrival. A screen reader reaching one mid-animation reads `[ WHAM A 5150B58P D5 ]`, and in a backgrounded tab it never resolved. | Fixed — the real string is now an `.sr-only` sibling; the animated copy is `aria-hidden` |
| A4 | The hero's Now / Based / Open-to block was three `<div>`s with a coloured `<span>`. The key/value relationship existed only in the punctuation. | Fixed — `<dl>` with `<dt>`/`<dd>`, inline on desktop, two-column on mobile |
| A5 | The entire toolchain lived only in an `aria-hidden` marquee: unreadable by a screen reader, a search engine, and anyone skimming for one keyword. | Fixed — new `#stack` section, see §3 |
| A6 | `<html lang>` was fixed at `en` with no way to express the other three languages. | Fixed — resolved before first paint, `hreflang` alternates, per-locale `og:locale` |
| A7 | The portrait slot inherited the atmospheric photo treatment — `opacity:.58` with `mix-blend-mode:screen` on near-black. Correct for a backdrop, wrong for the one image a reader uses to recognise a candidate: the face read as a ghost. | Fixed — full opacity, normal blend, grayscale and contrast kept so it stays inside the page's grammar; checked in both themes |

### Keyboard, checked by hand because axe cannot

The horizontal reel is pinned and scrubbed by `scrollY`, so a focused card can sit off-screen with a
focus ring nobody can see. Tabbing through it at 1440 × 900 with the pin active: each of the four
cards' links took focus **inside the viewport with its whole card visible** (card lefts 35 → 339 →
636 → 925 as the rail translated), every one with a 2px ring, and tab five left the reel cleanly
into the "Also shipped" list. Chrome tab order is also correct: skip link → four jump links →
language → theme → email pill → hero buttons, all in view, all ringed.

### Contrast, computed rather than sampled

axe returns 44 `incomplete` contrast nodes because the chrome uses `backdrop-filter` and the frames
use blend modes; those are computed here directly from the token set.

| Token | on ground | on surface | on surface-2 |
|---|---|---|---|
| `--bone` dark / light | 16.15 / 15.20 | 15.07 / 17.63 | 14.20 / 13.76 |
| `--bone-2` dark / light | 7.44 / 7.91 | 6.94 / 9.18 | 6.54 / 7.16 |
| `--muted` dark / light | 5.33 / 5.06 | 4.97 / 5.87 | 4.69 / 4.58 |
| `--accent` dark / light | 5.32 / 5.27 | 4.96 / 6.11 | 4.68 / 4.77 |

### Standing limitations

- The photographic captions sit on a 74–88% scrim over a blended photograph. Contrast is high in
  practice but is not token-guaranteed; it is the one place on the page where a future photograph
  could degrade it.
- Twelve-pixel monospace carries roughly twenty label roles. It passes contrast; it is small.

### 3.2 Gaps closed

1. **Role, employer and dates within the first screen.** The recruiter screening this page reached no
   employer and no date until the timeline at roughly 7,600px. The hero now reads
   "AI Engineer at DFlo, Jul 2025 – present · 3 years shipping production AI".
2. **Availability stated, not implied.** "Full-time or fixed-scope contract · available immediately".
3. **The stack as a document.** Five groups — vision and models, language and agents, backend and
   data, interface, cloud and operations — in reading order, in a `<dl>`, translated, indexable, and
   introduced by "Everything below is in a system that shipped, not on a course certificate".
4. **The casino claim qualified.** "Two classes — customer and staff — detected under camera
   placements that had defeated earlier attempts". The claim is unchanged; its scope is now stated.
5. **`Person` JSON-LD**, canonical URL, four `hreflang` alternates and an `x-default`.

Nothing was added that the CV does not support. Where the CV does not state a fact — the GPU model
behind the 95% mAP figure, the dataset, the class threshold — the page stays silent rather than
inventing a qualifier.

### 3.3 Content model

The model is the dictionary: **167 keys**, one per addressable string, flat and dotted by section.
Four value shapes, and the shape determines how the runtime writes it:

| Shape | Binding | Used for |
|---|---|---|
| string | `data-i18n` → `textContent` | most copy |
| string with inline markup | `data-i18n-html` → `innerHTML` | strings carrying `<b>`, `<strong>`, `<br>` |
| string | `data-i18n-attr="attr:key"` | `alt`, `aria-label` |
| array of 3 | `data-i18n-lines` → one entry per `.ln` | display headlines, where the line breaks are authored |

Screen-reader-only keys (`*.alt`, `*.aria`) are full sentences and are never displayed. Numerals,
units, product names and technology names are protected and identical across all four dictionaries.

### 3.4 Voice and tone

**Voice:** first person, concrete, unembellished. Claims carry a number and a route to check it.

| Register | Where | Example |
|---|---|---|
| Declarative | headlines, principles | "Anyone can make a model agree with them." |
| Evidential | cards, metrics | "120 RPS at TP95 · in commercial use" |
| Reassuring | contact, NDA notes | "I reply within two business days" |
| Plain descriptive | alt text, aria labels | "A supermarket aisle photographed straight on…" |

Counter-examples, all avoided: superlatives without a number; "passionate", "cutting-edge",
"leverage"; any claim that the CV does not support.

### 3.5 Governance

- **Source of truth for English is the markup.** There is no `en` dictionary in the runtime. English
  is read out of the DOM at boot, so the authored copy and the English strings cannot drift — and
  the copy a reader sees with JavaScript disabled is the same copy.
- **Source of truth for the other three is `design/i18n/{vi,ja,zh}.json`,** mirrored into the inline
  `<script type="application/json">` blocks in `index.html` so the file stays openable from disk.
  The mirror is a script, not a ritual: **`python3 design/i18n/sync.py`** checks parity and then
  rewrites the three inline blocks; `--check` verifies without writing. It exits non-zero on any
  mismatch, so it belongs in whatever runs before a deploy. Current state:

  ```
  $ python3 design/i18n/sync.py --check
  parity ok: 167 keys requested, 167 per dictionary, 3 locales
  ```

  It derives the contract from the page rather than from a second copy of the English strings: the
  `data-i18n*` attributes plus the keys the scripts resolve through `tr()`/`t()`. It fails on a key
  the markup wants and a dictionary lacks, a key set that differs between locales, a headline array
  that is not exactly three entries, an inline-tag sequence that differs from the reference locale,
  and a dictionary key nothing consumes. That last check is what caught `ticker.aria` and
  `work.reel.aria`, both since removed.
- **Adding or changing a string:** add it to the markup with `data-i18n="<key>"`, then add the key to
  all three JSON files and re-run the mirror. A missing key falls back to English rather than
  rendering blank, so a half-finished translation degrades one string, not one page.
- **Adding a locale:** copy any existing dictionary — its key set, in order, *is* the contract — then
  add an `<option>`, an `hreflang` link, an `og:locale:alternate`, and an `OG[]` entry. If the
  dictionary fails to parse, the runtime removes that option rather than offering a switch that
  does nothing. There is deliberately no `en.json`: a second copy of the English strings that the
  page never loads is the one file guaranteed to go stale.
- **Parity check before publishing** — key set, key order, array lengths, and the sequence of inline
  HTML tags per value must match across the three dictionaries, and every `data-i18n*` key in the
  markup must exist in all of them. Enforced by `sync.py`, not by hand. Verified: 167 requested,
  167 per dictionary, zero missing, zero orphaned.
- **Review cycle:** the dated facts (commit counts, "updated September 2026", the PDF size, the
  "present" end date) are the parts that rot. Re-check them whenever the CV is regenerated.

## 4. Multi-language

One document, four locales, selected client-side and remembered.

- **Resolution order:** `?lang=` (so a locale is linkable and indexable) → `localStorage` → browser
  preference → English. Settled in the `<head>`, before `<body>` is parsed, because the locale
  typography rules key off `<html lang>`: doing it later would arrive as a reflow.
- **Switching** rewrites text, inline markup, attributes, headline lines, the card schematic labels,
  `<title>`, the meta description, `og:locale`, `<html lang>` and the URL — without a reload — then
  dispatches `langchange` so the marquee re-measures its loop and the theme button re-reads its label.
- **Typography per locale, not per font stack.** Glyph coverage is left to the browser's last-resort
  fallback — no shipped webfont has CJK and every stack ends in a generic family, so a hand-written
  CJK stack would only duplicate the font matcher. What the matcher cannot fix is handled explicitly:
  uppercasing and 0.13–0.24em tracking are removed for CJK (both only damage it), leading opens from
  0.9 to 1.18–1.78, measures narrow to ~38em, and Vietnamese gets the headroom its stacked diacritics
  need above a capital at 0.9 leading.
- **Locale rules are written `:root:lang(ja)`, not `:root[lang="ja"]`.** `:lang()` matches subtags,
  so the ninety-odd locale selectors keep working the day the runtime emits `zh-Hans` or `ja-JP` —
  which is what `og:locale` already says and what correct Han glyph selection eventually wants. An
  attribute selector would have failed silently and en masse.
- **Degradation:** a dictionary that fails to parse costs that language, not the page. Every
  script-owned string has an English fallback argument, so an i18n failure yields English, not a
  blank label.

## 5. What was not changed, and why

- **The 3D tilt, glare and magnetic buttons.** A sceptical technical reader discounts them, but they
  are authored, gated on a fine pointer, and disabled under reduced motion. Taste, not a defect.
- **The drawn card schematics.** Replacing them with real output frames would be stronger evidence,
  but the systems are behind client NDAs and the page says so.
- **The marquee.** Now that the stack is a document, the marquee is honestly decorative and correctly
  `aria-hidden`.
- **12px monospace labels.** They pass contrast. Raising them is a design decision, not a fix.

## 6. Premium pass and the detector

A later pass on perceived quality and on section-change feedback.

### 6.1 The detector

A fixed instrument, bottom-left, that follows the scroll, locks onto the section you reach, and
names it: `[⌖] 05 / 08 · HOW I WORK`, over a hairline showing travel through the whole document.

It is **not a mascot**, and that was the decision, not an omission. The page's audience is a CTO or
a hiring manager screening an AI engineer; a cartoon companion would cost credibility with exactly
the reader it was meant to charm. But the h1 already says *watch, judge, report*, so the companion
is the detector itself — the page performing its own thesis instead of restating it. Every part is
vocabulary the page already owned: the bracket from the favicon and the cursor reticle, the
acquisition scale from `.field .det`, the middot separator, the mono label grammar.

Decisions worth recording:

- **The section name does not decode on change.** A section boundary is crossed a dozen times per
  visit — the tier where motion must be near-imperceptible or absent. The bracket acquisition
  (one shot, 500ms, peripheral) is the state signal; the name just swaps. A 900ms scramble firing
  twelve times would charge attention on every crossing for no added information.
- **A jump-link click is the one place it performs.** Rare and deliberate, so the reticle opens into
  a `seeking` loop for the 820ms of the scroll, then locks on arrival. That is the "switching
  section" effect, and it is attached to the only navigation that is actually a switch.
- **No page-transition wipe.** This is one scrolling document with a pinned reel already competing
  for the scroll; an overlay between sections would be scroll-jacking.
- **Labels are read from the translated eyebrows,** not from new dictionary keys. Zero keys added,
  and the instrument localises for free — it re-reads on `langchange`.
- **It hides while the reel is pinned,** because the reel runs its own `01 / 04` readout in the same
  corner. Two instruments is one too many.
- `aria-hidden`. It reports scroll position, which a screen reader already gets from the headings
  and the dock's `aria-current`. A live region firing on every section would be noise.

### 6.2 Material

| Change | Why |
|---|---|
| **Theme switch no longer smears.** Transitions are suppressed for one frame across the flip, then restored. | Every colour transition on the page — dock links, buttons, cards, contact links, footer — fired simultaneously on a theme change, so the switch dissolved over ~400ms instead of snapping. Verified: `transition-property` on `.dock a` reads `none` during the swap and `color` after. |
| **Cards carry a lit top edge** (`inset 0 1px 0`). | The single largest perceived-quality cue on a dark surface: it gives the panel thickness and implies the same light source as the hero bloom. Re-stated in the hover and focus shadows, since `box-shadow` is one property and a bare elevation shadow would have dropped it. |
| **Image edges are an outline, not a border.** New `--img-outline` token: pure white at 10% on dark, pure black at 12% on light. | `--line` is a tinted neutral; against a photograph a tinted edge picks up the surface beneath and reads as dirt on the image rather than as a frame. |
| **Press feedback `0.97` → `0.96`.** | 0.97 is under the threshold where the press registers at all. |
| **The house curve is now a token.** `--ease-out: cubic-bezier(.2,.9,.3,1)`, plus `--ease-acquire` for the one-shot lock. | The curve was already written out nineteen times. It is named rather than replaced — introducing a second ease-out beside an established one is how a motion language stops being one. |

### 6.3 Verified

16 combinations (4 locales × 4 widths, alternating themes): axe 0 violations, no overflow, the
instrument on-screen and clear of both the dock and the email pill at every width (107px wide at
320, 274px at 1440 in its widest locale), zero console errors. Under `prefers-reduced-motion` it
still reports position and never animates — `animation-name` resolves to `none` and the lock class
is never applied.

## 7. The guided tour

The detector speaks. Seven stops; on reaching one it names the section and adds a single line of
guide copy, in the register of a good game tutorial — a knowledgeable guide pointing at things,
never a mascot, no greeting, no exclamation marks.

### 7.1 Contract

- Copy lives on each `<section>` as **`data-guide`**, bound with `data-i18n-attr`. No key table in
  the script, no new mechanism: it is translated and parity-checked exactly like every `alt` and
  `aria-label`, and `sync.py` validates it. Two sections carry two pairs each, which is what made
  the multi-pair parsing in `sync.py` load-bearing.
- 10 keys: `guide.s1`–`guide.s7`, `guide.off`, `guide.on`, `guide.on.label`.
- On by default; `[×]` dismisses permanently to a `?` pill, remembered in `localStorage`.

### 7.2 Decisions, with the reasoning that produced them

| Decision | Why |
|---|---|
| **It retracts, it does not camp.** Dwell is computed from the string in front of the reader — `4200 + weight × 52`, CJK characters weighted 1.6×, clamped 6.5–15s. | A hint that stays up is an obstruction. Measured: EN 11.3s, VI 11.4s, JA 11.9s — Japanese lands longest on a third the characters, which is the point of weighting rather than counting. |
| **`pointer-events: none` on the panel; only the button is interactive.** | This was briefly `auto` to allow hover-pause, and it cost a measured conversion: at 85% scroll the panel's box sat over "Start a conversation" and `elementFromPoint` resolved the click to the panel. Hover-pause moved onto the button, which can never be the thing covering a CTA. |
| **WCAG 2.2.1** satisfied by the dismiss control (turn off, available at first encounter) plus pause on hover/focus of the button. | It is a time limit on reading; the exception list does not cover it. |
| **The brief is exposed to assistive technology; the readout is not.** | Hiding the tour while offering a screen-reader user a "turn off the guided tour" button is incoherent. Not a live region — announcing on every section boundary during a scroll would be chatter. |
| **The panel is `visibility: hidden` when down, not just `opacity: 0`.** | Opacity alone left the dismiss button in the tab order while invisible. Verified: 9 × Tab never reaches it. |
| **The tour ends when `#contact` enters the viewport.** | See §7.3. |

### 7.3 Two rejected fixes, and why the third is right

The panel's corner and the close section's CTAs are the same corner. Three attempts:

1. **Per-frame geometric guard** — hide whenever any closing control would sit under the panel.
   Rejected on measurement: it flickered `off/ON/off/ON` across 86–94% of the page, and every flip
   back re-entered `expand()` with a fresh dwell, so the hint never retracted through the whole
   close section. A blinking panel is a worse defect than the overlay it prevented.
2. **Exclude `#contact` from the stops** — not sufficient. The panel went on showing the *previous*
   stop's hint while the reader was already inside the close section: clearance to the CTA row was
   **−38px at 1280** and **−152px at 320**. The 1440 case cleared only because that stop's hint
   happens to wrap to one line fewer, which is luck, not design.
3. **Stand down when `#contact` enters the viewport** — one rect, one element, monotonic while
   scrolling down so it cannot flicker. Verified at five widths on the dock-jump arrival: panel
   off, zero controls covered; and a 16-sample sweep shows a single transition at 82%.

The cost is the closing line, which was the least informative of the eight and duplicated the lede
beside it. The tour now runs 07/07 and ends before the conversion section. That trade is the right
way round: no tour copy is worth standing on "Start a conversation".

### 7.4 Verified

16 combinations (4 locales × 4 widths, alternating themes): axe 0 violations, no overflow, 0 console
errors, 7 stops in every locale. Closing behaviour checked on all three arrival paths — dock jump,
`#contact` deep link, document floor — at 320 / 390 / 1024 / 1280 / 1440.

## 8. The work reel: navigation and jargon

Two complaints, needing opposite treatments: the pinned horizontal deck was hard to *move around*,
and the cards were hard to *understand*. Decoration would have made both worse, so the decoration
is last and smallest.

### 8.1 Navigation — a stepper, and the bug it exposed

The progress bar was read-only and `aria-hidden`. It is now a `<nav>` of four real buttons: each
takes its accessible name from its own card's heading, so it localises with no keys of its own,
and the current card is marked with `aria-current`.

Wiring it up surfaced a defect that had been in the reel from the start:

| | Before | After |
|---|---|---|
| Rail travel | `scrollWidth − innerWidth + 60` | measured from the last card's `offsetLeft + offsetWidth + padding` |
| Cards the scrub could centre | **0, 1, 2** — never 3 | 0 → 1 → 2 → 3 |
| `01 / 04` readout | could never display `04` | reaches every card |

Two causes, both measured:

1. **No end padding.** The rail started with the first card left-aligned and stopped with the last
   one right-aligned, so neither end could ever be the card nearest the centre. The rail now carries
   half a viewport minus half a card at each end, recomputed on refresh because the card width is a
   `clamp()` of the viewport.
2. **`scrollWidth` drops trailing padding on a flex row.** Adding the padding was not enough — the
   travel still came out half a viewport short. Distance is now derived from the last card's
   geometry instead.

Jump targets solve for the scroll offset that *centres* a card rather than interpolating `i/(n−1)`
across the scrub, which put "card 4" at the end of the rail rather than in the middle. Keyboard
focus uses the same function, so a tabbed card and a clicked step land identically. Verified: all
four jumps land within 7px of centre with the matching step marked.

### 8.2 Jargon — explanation without tooltips

`Triton`, `ONNX`, `mAP`, `TP95` are opaque to the person deciding whether to forward this page.
Every technology tag and every headline figure now carries one plain sentence — 19 new strings,
translated into all four languages.

The delivery is deliberately not a tooltip, and it has three input paths because each one fails
differently:

- **Screen reader** — the sentence lives in the DOM as `.sr-only` text *inside* the tag, so it is
  read inline with no interaction at all. One source of truth: the visible overlay reads that same
  node, so announced and shown text cannot diverge.
- **Pointer** — hover, gated on `(hover:hover) and (pointer:fine)`.
- **Touch** — click toggles. The first implementation only listened for `pointerenter`/`pointerleave`,
  which on a tap fire back to back: the sentence flashed for 140ms and vanished. The toggle then
  broke a second way — a tap fires `focus` before `click`, `focus` opened the panel, and `click`
  saw its own open and closed it again. The pre-state is now captured on `pointerdown`.
- **Keyboard** — each card's tag list is **one** tab stop with arrow keys inside it (`Home`/`End`
  too). Fifteen tab stops in one section would have wrecked keyboard navigation of the page; four
  gives a sighted keyboard user the same access a mouse user has. Verified: `tagStops = 4`, whole
  page 35 focusable elements.

**WCAG 1.4.13** (content on hover or focus) applies and is met: dismissible by `Escape` and by a
click outside, hoverable because the slot sits inside the card that triggered it, and persistent
until dismissed. The first version had none of this — it was hover-only with no keyboard path and
no dismiss, which is the gap this pass closed.

### 8.3 Glitch, scoped

A four-frame channel-split and a single scanline, on the **schematic only**, fired once when a card
becomes the centred one. Not on type — glitching the text would cost legibility on the one section
that has to be read — and not on hover, which would fire it dozens of times per visit. Suppressed
entirely under `prefers-reduced-motion`: verified `animation-name: none` and no `.glitch` class
ever applied.

### 8.4 Verified

12 combinations (4 locales × 3 widths, alternating themes): axe 0 violations, no overflow, 0 console
errors, stepper present and 34px at the pinned sizes and correctly absent below the pin gate,
explanation present in every locale. Keyboard: exactly **one tab stop per card** over the tags and
the headline figure (4 across the reel, 35 focusable elements on the whole page), arrows and
`Home`/`End` walking the set, `Escape` dismissing. Touch verified with real taps — open, toggle
closed, switch source, dismiss by tapping elsewhere. Scrub sweep reaches `0 → 1 → 2 → 3`; the
glitch fires exactly once per card change (8 class mutations across 4 changes).
